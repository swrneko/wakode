# wakode — дизайн

**Дата:** 2026-08-15
**Статус:** согласовано, готово к написанию плана реализации

## 1. Цель

Опенсорсный selfhosted-сервис учёта времени разработки, совместимый с экосистемой плагинов WakaTime на уровне HTTP-протокола. Пользователь меняет `api_url` в `~/.wakatime.cfg` и продолжает работать теми же плагинами, но данные хранятся на его сервере.

Критерий успеха волны 0: владелец инстанса перестаёт пользоваться wakatime.com и не испытывает неудобств.

### Чем оправдано существование проекта

Wakapi (Go) уже решает базовую задачу. wakode отличается тремя вещами, которых нет ни у WakaTime, ни у Wakapi:

1. **Неизменяемое сырьё и слои поверх** — правила, ручные записи и перекрытия применяются при чтении, поэтому любое изменение обратимо, а история никогда не портится.
2. **Импорт цветовой схемы редактора** — дашборд выглядит как рабочее окружение пользователя.
3. **Аналитика ИИ-ассистированного кода** — WakaTime уже собирает эти поля в heartbeat'ах, но selfhosted-аналоги их не используют.

## 2. Принятые решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Площадь совместимого API | Ядро ingest+summaries, плюс `/stats` и SVG-бейджи во второй волне | Ось «плагины пишут к нам» стоит два эндпоинта и даёт 95% обещания. Полный v1 добавляется аддитивно. |
| OAuth2-провайдер | Не делаем | Сторонние клиенты хардкодят домен wakatime.com в OAuth-эндпоинтах; совместимостью некому пользоваться. |
| Многопользовательность | Да, схема с первого дня; регистрация выключается флагом | Ретрофит user_id — болезненная миграция, обратное — бесплатно. |
| Команды | Только агрегаты и лидерборд | Пути к файлам и ветки не покидают личный контур; исключает превращение продукта в инструмент слежки. |
| Поставка | Один бинарь со вшитой статикой | Node в проде отсутствует. Деплой — копирование файла. |
| Фронтенд | Vite + React + TS (не Next.js) | При статической сборке Next не даёт преимуществ и добавляет ограничения export-режима. |
| Хранилище | SQLite за репозиторным трейтом | Однофайловый бэкап, отсутствие внешнего сервиса. Postgres добавляется позже без переписывания логики. |
| Вычисление длительностей | На лету из сырья, метки грязных дней на будущее | Корректность по построению, нулевая инвалидация. Наивная реализация остаётся эталоном для property-тестов. |
| Интеграция с wakatime.com | Только импорт дампа, без relay | Решение владельца. Следствие: проверка совместимости целиком на golden-фикстурах. |
| Правила и редактирование истории | Применяются при чтении, heartbeats append-only | Любое правило обратимо, оригинал не теряется, импорт не конфликтует с правилами. |
| Авторизация | Серверные сессии + несколько именованных API-ключей | Мгновенный отзыв, потеря одной машины не требует ротации везде. |
| Первичные ключи | UUIDv7 во всех таблицах | Правило проекта; монотонность даёт хорошую локальность вставки. |
| Значение API-ключа | **UUIDv4** | Плагины валидируют ключ как UUID с проверкой версии `[1-5]`; v7 не пройдёт. |
| Кастомизация интерфейса | Фиксированные экраны + система тем с импортом base16 | Виджетная сетка откладывает точку переключения ради свободы, которая нужна единицам. |

## 3. Совместимый API

### Волна 0

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/users/current/heartbeats` | одиночная отметка |
| POST | `/api/v1/users/current/heartbeats.bulk` | батч, до 25 отметок |
| GET | `/api/v1/users/current` | профиль, проверка ключа |
| GET | `/api/v1/users/current/statusbar/today` | строка состояния в редакторе |
| GET | `/api/v1/users/current/summaries` | сводка за период |
| GET | `/api/v1/users/current/all_time_since_today` | суммарное время |

Аутентификация: `Authorization: Basic base64(api_key)`, а также `?api_key=`. Ключ может приходить с префиксом `waka_` — префикс срезается перед поиском.

### Волна 2

`GET /api/v1/users/:user/stats?is_including_today=true` и SVG-бейджи. Точный путь взят из исходников github-readme-stats: сегмента диапазона в пути нет, диапазон задаётся query-параметрами.

### Проверенные формы ответов

**Bulk.** CLI ожидает `{"responses": [[body, status], ...]}`, где элемент `[0]` — тело (`{"data":{"id":"..."}}` при успехе либо объект с полем `error`/`errors`), элемент `[1]` — код состояния этого элемента. Верхнеуровневый ответ — 201 или 202; успехом элемента считается любой 2xx.

**Одиночная отметка.** 201/202 с телом `{"data": {"id", "entity", "type", "time"}}`.

**`all_time_since_today`.** Сверено со снимком: верхний уровень — `data` **и `message`**; последнего в прежней редакции не было, а он приходит всегда (в снимке: «Calculating stats for this user. Check back later.»). `data`: `total_seconds`, `text`, `decimal`, `digital`, `daily_average`, `is_up_to_date`, `timeout`, `range`. Поля `percent_calculated`, обещанного прежней редакцией, в ответе **нет**. `range`: `start`, `end`, `start_date`, `end_date`, `start_text`, `end_text`, `timezone`.

**`summaries`.** Верхний уровень: `data[]`, `start`, `end`, `cumulative_total`, `daily_average`.
- `cumulative_total`: `decimal`, `digital`, `seconds`, `text`.
- `daily_average`: `days_including_holidays`, `days_minus_holidays`, `holidays`, `seconds`, `seconds_including_other_language`, `text`, `text_including_other_language`.
- элемент `data[]`: `grand_total`, `range`, и массивы `categories`, `projects`, `languages`, `editors`, `operating_systems`, `machines`, `dependencies`. Массивов `branches` и `entities` в ответе **нет** — прежняя редакция называла их по документации, снимок их не содержит; они приходят только при запросе с явным `project`.
- пустые дни в диапазоне присутствуют и имеют те же ключи: массивы пустые, `grand_total.text` — `"0 secs"`. Проверено снимком за 30 дней: 30 элементов `data[]`, из них 12 пустых. Требование спеки к `summaries` подтверждено чужим поведением, а не выведено.
- `start`/`end` верхнего уровня — границы в UTC, соответствующие полуночи **часового пояса аккаунта** (в снимке: `2026-07-19T21:00:00Z` для пояса Europe/Moscow).
- элемент массива: `name`, `total_seconds`, `seconds`, `hours`, `minutes`, `percent`, `digital`, `text`.
- `grand_total`: `total_seconds`, `hours`, `minutes`, `digital`, `text`.
- `range`: `date`, `start`, `end`, `text`, `timezone`.

**`statusbar/today`.** Официальной документации нет; форма снята с живого ответа. Верхний уровень — `{"data": <элемент data[] из summaries>, "has_team_features": <bool>}`. Поля `cached_at`, которое предполагала прежняя редакция, в ответе **нет**, зато есть `has_team_features`, которого она не предполагала.

**Оговорка про `ai_*`.** Снимок 2026 года несёт в `grand_total` и в элементах массивов десятки полей `ai_…` (`ai_sessions`, `ai_input_tokens`, `ai_model_costs`, …), которых нет ни в документации, ни в прежней редакции этого раздела. Волна 0 их не воспроизводит: плагины редакторов их не читают, а выдумывать значения хуже, чем не отдавать поле. Решение пересматривается, если найдётся потребитель.

### Поля heartbeat

Обязательные: `entity`, `type` (`file` | `app` | `url` | `domain`), `time` (float, unix-секунды).

Опциональные: `category`, `project`, `project_root_count`, `branch`, `language`, `dependencies` (строка через запятую), `lines`, `lineno`, `cursorpos`, `line_additions`, `line_deletions`, `is_write`, `user_agent`.

Поля про ИИ: `ai_line_changes`, `human_line_changes`, `ai_session`, `ai_input_tokens`, `ai_output_tokens`, `ai_prompt_length`, `ai_subscription_plan`.

Принимаем и храним всё перечисленное — модель является надмножеством, чтобы импорт ничего не терял.

## 4. Архитектура

Один процесс, один бинарь. Ни брокера, ни внешнего кэша, ни отдельного воркера — фоновые задачи на tokio внутри процесса.

Cargo workspace:

- **`wakode-core`** — доменные типы, движок длительностей, движок правил, свод в summary. Без обращений к БД, сети и файлам. Чистые функции над векторами структур.
- **`wakode-store`** — репозиторные трейты и реализация на SQLite, миграции, интернирование строк, дедупликация.
- **`wakode-api`** — axum. Подмодуль `compat` (форма WakaTime, заморожена чужим протоколом, покрыта golden-фикстурами) и подмодуль `internal` (для собственного фронта, свободен).
- **`wakode-web`** — статика SPA через `rust-embed`, заголовки кэширования, SPA-фоллбэк.
- **`wakode`** — бинарь: конфиг, запуск, CLI-подкоманды.

Изоляция `core` от I/O — главная граница проекта: property-тесты должны прогонять сотни тысяч сценариев в памяти за секунды.

Разделение `compat` и `internal` — следствие плана по волнам: полный v1 во второй волне добавляется как новые сериализаторы, не трогая вычислительный слой.

**Фронт:** Vite + React + TS, TanStack Router и TanStack Query, темы на CSS-переменных. TS-типы для `internal` генерируются из Rust через `ts-rs`.

## 5. Модель данных

### Интернирование строк

Таблица `strings(id INTEGER PRIMARY KEY, value TEXT UNIQUE)`; heartbeats ссылаются на неё вместо хранения текста. Выигрыш двойной: размер базы падает в разы, а словарь целиком помещается в память, поэтому чтение большого диапазона — это узкие строки с диска плюс подстановка из хеш-мапы в Rust.

### heartbeats

```sql
CREATE TABLE heartbeats (
  id            BLOB PRIMARY KEY,      -- UUIDv7, 16 байт
  user_id       BLOB NOT NULL,
  time          INTEGER NOT NULL,      -- микросекунды unix
  received_at   INTEGER NOT NULL,      -- когда приняли мы
  entity_id     INTEGER NOT NULL,      -- → strings
  type          INTEGER NOT NULL,
  category      INTEGER,
  project_id    INTEGER,
  branch_id     INTEGER,
  language_id   INTEGER,
  editor_id     INTEGER,
  os_id         INTEGER,
  machine_id    INTEGER,
  plugin_id     INTEGER,
  is_write      INTEGER NOT NULL,
  lines         INTEGER,
  lineno        INTEGER,
  cursorpos     INTEGER,
  line_additions INTEGER,
  line_deletions INTEGER,
  project_root_count INTEGER,
  dependencies  TEXT,                  -- как пришло, разбирается лениво
  ai_line_changes    INTEGER,          -- отдельными колонками: нужны для аналитики волны 2
  human_line_changes INTEGER,
  ai_meta       TEXT,                  -- остальные ИИ-поля как JSON, аналитикой не используются
  dedup_hash    INTEGER NOT NULL       -- 8 байт от содержимого
) WITHOUT ROWID;

CREATE UNIQUE INDEX hb_dedup ON heartbeats(user_id, dedup_hash);
CREATE INDEX hb_time ON heartbeats(user_id, time);
```

`time` и `received_at` — разные величины из-за оффлайн-очереди: отметка может прийти через дни после того, как случилась. Разделение даёт корректную пометку грязных дней и объясняет изменение вчерашних цифр.

`WITHOUT ROWID` — PK уже UUIDv7, скрытый rowid не нужен; вставки монотонны по времени и ложатся в хвост B-дерева.

`dedup_hash` — детерминированный 8-байтовый хеш от (пользователь, время, сущность, тип, категория, проект, ветка, признак записи). Вставка через `INSERT OR IGNORE`. При четырёх миллионах строк вероятность коллизии порядка `10⁻⁷`.

### users

UUIDv7, логин, e-mail (необязателен), argon2id-хеш пароля, отображаемое имя, **IANA-таймзона**, **личный таймаут сессии** (по умолчанию 900 секунд), признак администратора, отметки времени.

Таймзона определяет, что такое «сегодня»; вся дневная агрегация считается в Rust по этому полю через `chrono-tz`.

### api_keys

UUIDv7 как PK, ссылка на пользователя, имя («рабочий ноутбук»), `key_encrypted` (значение ключа под мастер-ключом из конфига, для показа в настройках), `key_lookup` (детерминированный HMAC от значения под тем же мастер-ключом, уникальный индекс — по зашифрованному значению искать нельзя, а аутентификация обязана находить ключ за один запрос), `last_used_at`, `revoked_at`.

Значение ключа — UUIDv4, выдаётся с префиксом `waka_`.

### sessions

UUIDv7, хеш токена, пользователь, срок действия, user-agent, отзыв.

### Слои поверх сырья (волна 1)

- `rules` — приоритет, включённость, тип совпадения (glob по сущности, регулярка по проекту, ветка, язык, префикс пути), паттерн, действие (задать проект / язык / категорию / исключить), значение.
- `overrides` — интервал и что переопределяем.
- `manual_entries` — интервал, введённый руками, с проектом, языком, категорией и заметкой.

Ни один из трёх не изменяет `heartbeats`.

### Служебные

- `dirty_days(user_id, local_date)` — задел под кэш агрегатов; пишется на вставке и при изменении правил.
- `imports` — статус разбора дампа.
- `teams`, `team_members` — схема с первого дня, экраны в волне 3.

## 6. Потоки данных

### Приём

Аутентификация по `key_lookup` → разбор и валидация → разбор `user_agent` на редактор/ОС/плагин → интернирование строк батчем → `INSERT OR IGNORE` → пометка затронутых локальных дней → ответ.

**Успех отдаётся только после коммита транзакции.** wakatime-cli, получив успех, удаляет отметки из своей локальной очереди; ответ до коммита плюс падение — безвозвратная потеря. Задержка ingest'а некритична, это фоновый процесс.

Запись идёт через **единственную пишущую задачу**: обработчики шлют батч по каналу и ждут подтверждения через oneshot. Убирает борьбу за блокировку SQLite и даёт групповую фиксацию батчей от разных пользователей в одну транзакцию.

Битая отметка не отменяет батч — per-item статусы в ответе.

### Чтение

Таймзона пользователя → перевод локальных границ в UTC-микросекунды → загрузка heartbeats за период **с запасом в один таймаут по краям** → применение правил → построение интервалов → агрегация → сериализация.

Запас по краям обязателен: сессия с 23:50 до 00:30 иначе развалится, и сумма за день не сойдётся с суммой за неделю.

### Импорт (волна 1)

Отдельная CLI-подкоманда — дамп может быть гигабайтным. Потоковый разбор JSON, батчи по несколько тысяч, тот же путь вставки с той же дедупликацией, в конце пометка затронутых дней. Повторный запуск на том же файле безопасен.

## 7. Движок длительностей

Отсортировать отметки по времени, идти парами. Если разрыв не больше таймаута — интервал записывается на счёт **более ранней** отметки (её проект, язык, ветка, категория). Разрыв больше таймаута — сессия рвётся, пауза не засчитывается.

Последняя отметка сессии не имеет пары. Величина добавки, которую ей начисляет WakaTime, в документации отсутствует и **подлежит калибровке по живому аккаунту**. В `core` это явный параметр, не константа.

Порядок применения слоёв:
1. Правила — к каждой отметке до группировки (меняют атрибуты, не время).
2. Построение интервалов.
3. Перекрытия — к готовым интервалам.
4. Ручные записи — вливаются как готовые интервалы.

При пересечении ручной записи с посчитанными данными **приоритет у ручной**: она введена человеком осознанно.

## 8. Ошибки и отказоустойчивость

- **Переполнение канала записи** → `503` с `Retry-After`. Это замысел, а не деградация: cli складывает отметки в свою очередь и досылает позже. Буферизация в памяти привела бы к потере при падении.
- **Часы клиента врут.** Отметки дальше нескольких минут в будущем отклоняются со внятной причиной; из прошлого принимаются любые (законный оффлайн-догон). Без отсечки одна сломанная машина рисует активность на месяцы вперёд.
- **SQLite** — WAL, `busy_timeout`, повтор при `SQLITE_BUSY`.
- **Миграции** применяются на старте; при несовместимости — отказ запускаться с понятным сообщением.
- **Мастер-ключ** не задан, а в базе есть зашифрованные ключи → отказ стартовать.
- **Паника в обработчике** ловится слоем и превращается в `500`.
- **Бэкап** — CLI-подкоманда поверх `VACUUM INTO`: консистентный снимок на живой базе.

## 9. Тестирование

TDD вертикальными срезами: один тест → одна реализация → следующий. Моки только на границах системы, а границ две — SQLite и исходящий HTTP (волна 1).

**`core` — property-тесты.** Инварианты:
- сумма по проектам равна общей сумме за период;
- интервалы одного пользователя не пересекаются;
- сумма за неделю равна сумме семи дней (граница полуночи);
- повторная подача тех же отметок не меняет результат;
- перестановка входного порядка не меняет результат;
- ни один интервал не длиннее таймаута.

Последние два ловят баги оффлайн-досылки, когда данные приходят не по порядку.

**`store`** — интеграционные тесты на временных файлах БД, через репозиторный трейт, а не через SQL: должны пережить переезд на Postgres без правок.

**`compat`** — снапшот-тесты против golden-фикстур, снятых с живого wakatime.com. Единственный способ узнать, что мы совместимы, а не думаем так. Особенно важно, поскольку relay отсутствует и других источников сверки нет.

**E2E** — поднять бинарь, натравить настоящий wakatime-cli с подменённым `api_url`, убедиться что отметки дошли и сводка сходится. Один сценарий в CI; требует скачивания чужого бинаря, что оправдано, поскольку совместимость с ним и есть суть проекта.

## 10. Волны поставки

**Волна 0 — точка переключения.** Конфиг (TOML с перекрытием из окружения), миграции, пользователи и сессии, именованные ключи, шесть совместимых эндпоинтов, внутренний API (сводка за период, разбивки по проектам/языкам/редакторам/ОС/машинам/категориям, таймлайн дня, список проектов), движок длительностей с property-тестами, CLI (миграции, создание пользователя, выдача ключа, бэкап). Фронт: вход, дашборд с переключением периода, страница проекта, настройки, система тем с импортом base16. Поставка: бинарь, Dockerfile, systemd-юнит, README.

**Волна 1 — контроль над данными.** Движок правил, склейка и переименование проектов, исключения, ручные записи, перекрытия, импорт дампа WakaTime.

**Волна 2 — аналитика.** Тепловые карты, фокус-сессии, контекст-свитчинг, разрезы по веткам, аналитика ИИ-полей. Плюс `/stats` и SVG-бейджи.

**Волна 3 — команды и геймификация.** Командные агрегаты, лидерборды, цели, стрики, ачивки.

**Волна 4 — интеграции наружу.** Webhooks, Prometheus, Grafana-дашборд, боты, MCP-сервер.

Схема данных заложена под все волны сразу; кода за пределами волны 0 нет. **План реализации пишется только на волну 0** — волны 1–4 зафиксированы здесь как направление, но детализируются отдельными спеками, когда до них дойдёт очередь.

## 11. Открытые вопросы

1. ~~**Добавка последней отметке сессии**~~ — **закрыт калибровкой.** Добавки не существует: последняя отметка сессии не даёт ничего. Модель WakaTime восстановлена точно и воспроизводит контрольный день до последнего знака — 62 интервала из 62, сумма 21839.3 с, совпадение с `durations`, с `grand_total` и с посуточными итогами по каждому проекту. Существенное следствие: зазоры меряются в **глобальном** порядке отметок и лишь потом приписываются проекту более ранней из пары; группировка по проекту заранее, как было заложено в движке, завышала итог на 13% на том же дне. Подробности и метод — `.claude/docs/decisions/no-tail-padding.md`.
2. ~~**Точная форма `statusbar/today`**~~ — **закрыт снимком**, см. раздел «Проверенные формы ответов».
3. **Полнота data dump на бесплатном тарифе** — вопрос волны 1.
